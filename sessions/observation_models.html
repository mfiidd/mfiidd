Observation models

Choosing how your model meets your data

Estimated time: 55 minutes | Requires: MCMC

Slides

Introduction

Every likelihood in this course so far has assumed that observed case counts follow a Poisson distribution:

obst∼Poisson(ρ⋅It)\text{obs}_t \sim \text{Poisson}(\rho \cdot I_t)

That is a modelling choice, and it makes a specific claim about how observation works. This session asks whether the claim holds, what happens when it does not, and what a likelihood is really doing when you fit with one.

Objectives

In this session you will:

  1. Critically evaluate observation model choices (Poisson, negative binomial)
  2. Check whether the Poisson variance assumption holds for real data
  3. Understand negative log-likelihood as an implicit distance metric
  4. Make informed choices about observation models for your own research

The model we are fitting

The transmission model is the deterministic SEIT4L model built in the Structure and stochasticity session, fitted here the same way as the deterministic comparison in the Particle MCMC session: R0R_0, the latent and infectious periods, the probability α\alpha of long-term immunity, the duration DimmD_\mathrm{imm} of temporary immunity, and ρ\rho, the fraction of infections that are reported, are all fitted alongside each other. A plain SIR cannot reproduce the second wave of this outbreak at all; the model checking session diagnosed that failure, and the SEIT4L model fixes it.

These two functions live in src/seitl_model.jl and arrived with using MFIIDD above.

function seit4l_ode!(du, u, p, t)
    R_0, D_lat, D_inf, α, D_imm = p

    β = R_0 / D_inf
    ϵ = 1.0 / D_lat
    ν = 1.0 / D_inf
    τ = 4.0 / D_imm  # Rate through each T sub-stage

    S, E, I, T1, T2, T3, T4, L, Inc = u
    N = S + E + I + T1 + T2 + T3 + T4 + L

    du[1] = -β * S * I / N + (1 - α) * τ * T4  # dS/dt
    du[2] = β * S * I / N - ϵ * E              # dE/dt
    du[3] = ϵ * E - ν * I                      # dI/dt
    du[4] = ν * I - τ * T1                     # dT1/dt
    du[5] = τ * T1 - τ * T2                    # dT2/dt
    du[6] = τ * T2 - τ * T3                    # dT3/dt
    du[7] = τ * T3 - τ * T4                    # dT4/dt
    du[8] = α * τ * T4                         # dL/dt
    du[9] = ϵ * E                              # dInc/dt (cumulative)
end

function simulate_seit4l_deterministic(θ, init_state, times)
    params = [θ[:R_0], θ[:D_lat], θ[:D_inf], θ[:α], θ[:D_imm]]

    u0 = [
        init_state[:S],
        init_state[:E],
        init_state[:I],
        init_state[:T1],
        init_state[:T2],
        init_state[:T3],
        init_state[:T4],
        init_state[:L],
        0.0,
    ]

    prob = remake(SEIT4L_BASE_PROBLEM; u0 = u0, p = params, tspan = (times[1], times[end]))
    sol = solve(prob, Tsit5(), saveat = times)

    state_names = [:S, :E, :I, :T1, :T2, :T3, :T4, :L, :Inc_cumulative]
    sol_matrix = reduce(hcat, sol.u)'
    df = DataFrame(sol_matrix, state_names)
    df[!, :time] = sol.t

    df[!, :Inc] = [0.0; diff(df.Inc_cumulative)]

    return df
end

The Poisson likelihood

What we have used so far

This is what we’ve been doing throughout the course:

@model function seit4l_poisson(times, init_state, n_obs)
    # Weakly informative priors, as in the Particle MCMC session
    R_0 ~ truncated(Normal(3.0, 2.0), lower = 1.0)
    D_lat ~ truncated(Normal(2.0, 1.0), lower = 0.5)
    D_inf ~ truncated(Normal(3.0, 2.0), lower = 0.5)
    α ~ Beta(2, 2)
    D_imm ~ truncated(Normal(15.0, 10.0), lower = 1.0)
    ρ ~ Beta(2, 2)  # Reporting rate

    # Simulate
    θ = Dict(:R_0 => R_0, :D_lat => D_lat, :D_inf => D_inf, :α => α, :D_imm => D_imm)
    traj = simulate_seit4l_deterministic(θ, init_state, times)

    # Reject parameter draws that drive the ODE solver to fail early; the NUTS
    # gradient probe occasionally lands on combinations where it only saves a
    # few timepoints
    if nrow(traj) != length(times)
        Turing.@addlogprob! -Inf
        return
    end

    # Likelihood: Poisson observation model
    lambdas = [max(ρ * traj.Inc[i + 1], 1e-10) for i in 1:n_obs]
    obs ~ arraydist(Poisson.(lambdas))

    return traj
end

NoteReminder: arraydist and | conditioning

obs ~ arraydist(Poisson.(lambdas)) declares a vector of independent Poisson observations, one per time point. The | operator, applied when creating the model instance below, conditions the model on the actual data. See the MCMC session for a full explanation of this pattern.

Does it reproduce the data?

Each fit is checked the same way.

function plot_predictive(model, chain, title)
    ## Draw replicate observations from the fitted model, one set per posterior draw
    predictions = predict(decondition(model), chain)
    draws = predictions[@varname(obs)]
    per_day = [[draws[i, 1][t] for i in axes(draws, 1)] for t in 1:length(flu_tdc.obs)]

    lower = [quantile(day, 0.025) for day in per_day]
    middle = [quantile(day, 0.5) for day in per_day]
    upper = [quantile(day, 0.975) for day in per_day]

    p = plot(flu_tdc.time, middle,
             ribbon = (middle .- lower, upper .- middle),
             linewidth = 2, color = :blue, fillalpha = 0.3,
             label = "95% predictive interval",
             xlabel = "Time (days)", ylabel = "Daily cases", title = title)
    scatter!(p, flu_tdc.time, flu_tdc.obs,
             label = "Observed", markersize = 3, color = :red)

    covered = count(lower .<= flu_tdc.obs .<= upper)
    return p, covered
end

What does Poisson assume?

The Poisson distribution has a key property: variance = mean

# Illustrate Poisson assumption
λ_values = [5, 20, 50]
p = plot(title="Poisson Distribution: Variance = Mean",
         xlabel="Count", ylabel="Probability")

for λ in λ_values
    dist = Poisson(λ)
    x_range = max(0, λ-20):min(λ+20, λ*2)
    plot!(p, x_range, [pdf(dist, x) for x in x_range],
          label="λ=$λ (σ²=$λ)", linewidth=2)
end
p
TipExercise: Does the assumption hold for our data?

The Poisson model claims the variance of the observations equals their mean. Check whether that is plausible for the Tristan da Cunha data.

  1. Fit the Poisson model above and extract the posterior mean trajectory.
  2. Compute the residuals (observed minus predicted) and their variance.
  3. Compare that variance against the mean prediction. If the data were Poisson, the two should be roughly equal.

What do you find, and what would it imply for the parameter estimates?

# Residual variance against mean prediction, under the Poisson fit
θ_fit = Dict(
    :R_0 => mean(chain_poisson[:R_0]), :D_lat => mean(chain_poisson[:D_lat]),
    :D_inf => mean(chain_poisson[:D_inf]), :α => mean(chain_poisson[:α]),
    :D_imm => mean(chain_poisson[:D_imm]),
)
pred_fit = mean(chain_poisson[:ρ]) .* simulate_seit4l_deterministic(θ_fit, init_state, times).Inc[2:end]
resid_fit = flu_tdc.obs .- pred_fit

println("mean prediction:    ", round(mean(pred_fit), digits = 2))
println("residual variance:  ", round(var(resid_fit), digits = 1))
println("ratio:              ", round(var(resid_fit) / mean(pred_fit), digits = 1),
        "  (Poisson demands 1)")
mean prediction:    5.32
residual variance:  11.3
ratio:              2.1  (Poisson demands 1)
TipSolution

The ratio printed above is around 2, above the 1 Poisson demands but nothing like the failure of the single-wave SIR: that model could not reproduce a second wave at all, which is exactly what SEIT4L was built to do. The fitted trajectory follows the overall rise and fall of the first wave and predicts about 314 of the 312 reported cases in total, essentially the right amount, though individual days can miss by a dozen cases or more, as day 7 below shows.

The overdispersion that remains is mostly real observation noise rather than a badly wrong mean. Two islanders infected in the same household are not independent draws, reporting was not perfectly uniform across the outbreak, and a population of 284 is small enough that demographic stochasticity shapes the outbreak rather than jittering it, which is the same point the Structure and stochasticity session made. The deterministic curve cannot represent that: it settles into a smooth, slowly decaying tail through the second wave, while the actual counts keep jumping between zero and a dozen. The single biggest miss is the peak itself, on day 7, where the trajectory predicts around 33 cases against the 47 reported, the kind of undershoot a genuinely stochastic peak in a small population can produce even when the mean dynamics are right.

Because the mean is no longer badly wrong, loosening the likelihood should move the posteriors much less than it would for a misspecified model. The next fit checks that.

Reasons the assumption might fail for epidemic data:

  • Under-reporting might be systematic rather than random
  • Behavioural changes might create clustering
  • Surveillance quality might vary over time
TipExercise: Predict what the negative binomial will change

Before you fit it, commit to an answer for each of these. Write them down — the point is to be caught out if you are wrong.

  1. Will the posterior for R0R_0 get wider, narrower, or stay about the same?
  2. Will the posterior mean of R0R_0 move much?
  3. The model adds one parameter, ϕ\phi. If the data were genuinely Poisson, what value would you expect the posterior for ϕ\phi to favour?

Then fit it below and check.

TipSolution

  1. Wider, but only modestly. The negative binomial can attribute a departure from the trajectory to observation noise, so the data pin the parameters down a little less tightly. Here the posterior standard deviation for R0R_0 and DinfD_\mathrm{inf} barely move, widening by a few per cent; DlatD_\mathrm{lat}, α\alpha and DimmD_\mathrm{imm} widen by noticeably more, by around two fifths as much again. ρ\rho widens the most, by about three fifths, because it is the parameter most directly pinned by the total case count, and that count is exactly where a few noisy days make the most difference.

  2. The mean barely moves, and that is no longer a surprise. The previous solution found the mean trajectory of SEIT4L already close to right, so there is little slack left for the negative binomial to redistribute. R0R_0 moves by well under one Poisson posterior standard deviation, but ρ\rho moves by close to one, the clearest sign that it is the parameter absorbing most of the redistributed residuals. Loosening an observation model only drags the mean along with it when the mean was wrong to start with. Here it mostly was not.

  3. Large ϕ\phi is the right answer to the question as asked, because variance is μ+μ2/ϕ\mu + \mu^2/\phi and the second term vanishes as ϕ→∞\phi \to \infty. The posterior for ϕ\phi sits near 5, some way below “large” but nowhere near the near-zero values a severely misspecified mean would demand. That fits real overdispersion, at a scale that household clustering and demographic noise in a population of 284 could plausibly produce, rather than a structural failure in the mean being mistaken for noise.

The negative binomial likelihood

What does the negative binomial assume?

The negative binomial keeps the same mean and adds a second parameter, so the variance is free to exceed it:

obst∼NegativeBinomial(μt,ϕ),Var(obst)=μt+μt2ϕ\text{obs}_t \sim \text{NegativeBinomial}(\mu_t, \phi), \qquad \text{Var}(\text{obs}_t) = \mu_t + \frac{\mu_t^2}{\phi}

where μt=ρ⋅It\mu_t = \rho \cdot I_t and ϕ\phi controls the overdispersion. Large ϕ\phi recovers the Poisson, and small ϕ\phi gives a much wider spread at the same mean.

# The same mean, three observation models
counts = 0:80
p = plot(title="Same mean of 20, different spreads",
         xlabel="Count", ylabel="Probability")

plot!(p, counts, pdf.(Poisson(20), counts),
      label="Poisson (σ²=20)", linewidth=2)

for φ in [5.0, 1.0]
    ## Julia parameterises the negative binomial by (r, p), so a mean μ with
    ## overdispersion φ is r=φ and p=φ/(φ+μ)
    dist = NegativeBinomial(φ, φ/(φ+20.0))
    plot!(p, counts, pdf.(dist, counts),
          label="NegBin φ=$(Int(φ)) (σ²=$(round(Int, var(dist))))", linewidth=2)
end

vline!(p, [20], color=:grey, linestyle=:dot, linewidth=2, label="Mean")
p

The extra variance grows with the square of the mean, so a day with a high predicted count is allowed to fall further from it than a day with a low one.

Everything else the Poisson assumed still holds. Observations are conditionally independent given the trajectory, and the same fraction of infections is reported on every day. Overdispersion is the only assumption the negative binomial relaxes.

TipExercise: what would you expect φ to be?

Look back at the ratio of residual variance to mean prediction you computed for the Poisson fit. If that ratio came entirely from overdispersion, and the mean prediction were about 5 cases a day, roughly what ϕ\phi would reproduce it?

Use Var=μ+μ2/ϕ\text{Var} = \mu + \mu^2/\phi and solve for ϕ\phi.

TipSolution

With μ=5\mu = 5 and a variance twice the mean, 10=5+25/ϕ10 = 5 + 25/\phi, so ϕ≈5\phi \approx 5. The fit below returns a ϕ\phi of about the same size, which is what should happen when the mean was already close to right: the back of an envelope calculation and the full fit agree because there is no structural misfit left for ϕ\phi to paper over.

Fitting it

@model function seit4l_negbin(times, init_state, n_obs)
    # Weakly informative priors, as in the Particle MCMC session
    R_0 ~ truncated(Normal(3.0, 2.0), lower = 1.0)
    D_lat ~ truncated(Normal(2.0, 1.0), lower = 0.5)
    D_inf ~ truncated(Normal(3.0, 2.0), lower = 0.5)
    α ~ Beta(2, 2)
    D_imm ~ truncated(Normal(15.0, 10.0), lower = 1.0)
    ρ ~ Beta(2, 2)
    φ ~ Exponential(10.0)  # Overdispersion parameter

    # Simulate
    θ = Dict(:R_0 => R_0, :D_lat => D_lat, :D_inf => D_inf, :α => α, :D_imm => D_imm)
    traj = simulate_seit4l_deterministic(θ, init_state, times)

    if nrow(traj) != length(times)
        Turing.@addlogprob! -Inf
        return
    end

    # Likelihood: Negative Binomial observation model
    mus = [max(ρ * traj.Inc[i + 1], 1e-10) for i in 1:n_obs]
    # NegativeBinomial(r, p) where r=φ, p=φ/(φ+μ)
    obs ~ arraydist([NegativeBinomial(φ, φ/(φ+μ)) for μ in mus])

    return traj
end
seit4l_negbin (generic function with 2 methods)
TipCode explainer
  • NegativeBinomial(r, p) - Julia’s parameterisation uses r (number of successes) and p (success probability). To get mean μ with overdispersion φ, use r=φ and p=φ/(φ+μ). This gives variance = μ + μ²/φ, so larger φ approaches Poisson, smaller φ gives more overdispersion.

Why the negative binomial?

A negative binomial is a Poisson whose rate varies from day to day with a gamma distribution, so it is what you get when the reporting rate is not constant and you have not modelled why. Clustered transmission produces the same shape: household outbreaks and superspreading events deliver several cases at once, so counts vary more than independent arrivals would.

Two weaker reasons also apply. It fits these data better than the Poisson, and it is cheap to evaluate inside MCMC.

What it does not do is tell you which of those mechanisms was at work, or distinguish any of them from a mean that is simply wrong.

The two fits differ in one thing: what they charge the model for a day that misses the prediction. That charge widened ρ\rho the most above, so it is worth looking at on its own.

Interlude: likelihood as distance

Likelihood as distance

The negative log-likelihood is actually a distance function between observed and predicted data:

Distance=−log⁡p(obs|predicted)\text{Distance} = -\log p(\text{obs} | \text{predicted})

We can see what distance each likelihood implies:

# Compare different observation models as distance functions
obs_val = 10.0
predicted_range = 1.0:0.5:20.0

# Poisson: -log P(obs | λ)
poisson_distance = [-logpdf(Poisson(λ), obs_val) for λ in predicted_range]

# Negative Binomial with different φ (convert to r,p parametrization)
# NegativeBinomial(r, p) where r=φ, p=φ/(φ+μ)
negbin_distance_phi5 = [-logpdf(NegativeBinomial(5.0, 5.0/(5.0+λ)), obs_val) for λ in predicted_range]
negbin_distance_phi20 = [-logpdf(NegativeBinomial(20.0, 20.0/(20.0+λ)), obs_val) for λ in predicted_range]

# Gaussian (for comparison)
gaussian_distance = [-logpdf(Normal(λ, 3.0), obs_val) for λ in predicted_range]

# Plot
plot(predicted_range, poisson_distance,
     label="Poisson", linewidth=2,
     xlabel="Predicted value", ylabel="-log(likelihood)",
     title="Different Likelihoods as Distance Functions (obs=10)",
     legend=:topright)
plot!(predicted_range, negbin_distance_phi5,
      label="NegBin(φ=5)", linewidth=2)
plot!(predicted_range, negbin_distance_phi20,
      label="NegBin(φ=20)", linewidth=2)
plot!(predicted_range, gaussian_distance,
      label="Gaussian(σ=3)", linewidth=2, linestyle=:dash)

Each curve is at its lowest where the prediction meets the observation and rises as the two part company. What differs is how steeply, and on which side:

  • Poisson: penalises deviations relative to the predicted value rather than in absolute cases, so the same gap costs more at a low prediction than at a high one
  • Negative binomial: the same shape with a much flatter upper tail, so a prediction well below the observation costs little
  • Gaussian: penalises the absolute gap symmetrically, at a cost that does not depend on the size of the counts

The flat tail widened the fit. Day 7, the observed peak, reports 47 cases where the mean trajectory of the Poisson fit predicts about 33:

# What each observation model charges for day 7
day7 = findfirst(==(7), flu_tdc.time)
obs_day7, pred_day7 = flu_tdc.obs[day7], pred_fit[day7]

println("Poisson:  ", round(-logpdf(Poisson(pred_day7), obs_day7), digits = 1))
println("NegBin:   ", round(-logpdf(NegativeBinomial(φ_fit, φ_fit/(φ_fit+pred_day7)),

Poisson:  5.3
NegBin:   4.3

The Poisson is charged a little more for that single day than the negative binomial, not the order-of-magnitude gap a badly wrong mean would produce. That is the comparison table above, seen from the observation model rather than from the chain: a likelihood that charges a little less for a missed day leaves the parameters only a little freer to go elsewhere, consistent with a mean that was already close to right.

Learning points

TipLearning points
  • An observation model is a claim about how cases reach the data. The common choices have a mechanism behind them, and a negative binomial is a Poisson whose rate varies, which is what clustered transmission and uneven reporting both produce
  • The Poisson assumption that variance equals the mean is testable, and surveillance data routinely breaks it
  • A negative log-likelihood is a distance function, so choosing an observation model is choosing how to measure the gap between prediction and data
  • An observation model that is too tight makes the posterior overconfident. Loosening it widens the intervals and moves the mean, but a mean that is wrong for structural reasons is not fixed by the observation model
  • Some problems look like observation-model problems and are not. A delay between an event and its report, or a reporting fraction that changes part-way through an outbreak, needs a change to the model rather than a wider likelihood
TipExercise: Which observation model for which system?

The choice is not abstract. For each of these surveillance systems, say which observation model you would start with and what feature of the system drives the answer.

  1. A sentinel network of GP practices reporting influenza-like illness weekly, with stable participation and no weekend effect.
  2. Notifications of a rare disease, where a single case triggers an investigation that often finds several more in the same household.
  3. Deaths in a national registry, complete but reported with a delay that varies between one and three weeks.
  4. A new pathogen where testing capacity tripled part-way through the outbreak.
TipSolution

  1. Poisson is defensible. Stable reporting, no obvious clustering, and cases arriving independently is roughly what Poisson assumes. Check the variance against the mean anyway rather than assuming.

  2. Negative binomial. Case-finding around an index case produces exactly the clustering that breaks the independence assumption, and the visible symptom is variance far above the mean.

  3. Neither, on its own. The problem here is not the spread but the timing: a case counted this week may belong to three weeks ago. No observation model fixes that. You need a delay distribution between the event and its report, which is a change to the model rather than to the likelihood family.

  4. Neither, again. Tripling testing changes the proportion of infections you observe partway through, so a constant reporting fraction ρ\rho is wrong. You need ρ\rho to vary with time. Fitting a fixed ρ\rho here will make the model infer a change in transmission that never happened.

The general point: 1 and 2 are observation-model choices, 3 and 4 look like them and are not. Asking “is this about how much noise, or about what the data mean?” separates the two.

Going further

Other observation models

The choice of observation model affects inference more than many researchers realise. Consider exploring:

  • Gaussian likelihood: Appropriate when counts are large and approximately symmetric
  • Zero-inflated models: When surveillance systems miss entire days
  • Reporting delay models: When cases are reported with variable lag

Computing the variance/mean ratio in your data can help diagnose whether Poisson (ratio ≈ 1) or Negative Binomial (ratio > 1) is more appropriate.
