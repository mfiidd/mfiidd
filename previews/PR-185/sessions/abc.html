Approximate Bayesian computation

Inference when you cannot write down a likelihood

Estimated time: 60 minutes | Requires: Observation models

Slides

Introduction

For many models you cannot evaluate p(y∣θ)p(y \mid \theta), but you can still run the model forward. Approximate Bayesian computation is built on that alone: draw parameters from the prior, simulate a dataset, and keep the parameters whose simulation came out equal to the data. Nothing is approximated at that point, and the parameters you keep are draws from the posterior.

ABC runs the simulator from beginning to end and compares the output with the data through a distance you choose. That is the whole of what it needs from a model. It never opens the simulator up, and it never asks for the probability of an observation.

Objectives

In this session you will:

  1. Say what ABC needs from a model, and what it does not
  2. Read an ABC rejection sampler and choose a workable acceptance threshold, which is the hard part of the method
  3. Explain why ABC-MCMC stalls at a tight threshold, and how ABC-SMC reaches one
  4. Compare likelihood-based and distance-based posteriors on the same data
  5. Say how each approach responds to a single outlying observation

The model we fit

We keep the SEIT4L model from the particle filter and particle MCMC sessions, simulated stochastically. Run it twice at the same parameters and you get two different epidemics, so there is no single curve to hold against the data.

The particle MCMC session already fitted this model, and fitted it better than this session will. It estimated all six parameters where we estimate three, and it reached a tighter posterior from fewer simulations. On this outbreak the particle filter is the better tool, and we use the same model anyway so that you can hold ABC against an answer you already trust.

ABC earns its place where the particle filter cannot run at all. The filter weights each particle by an observation density p(yt∣xt)p(y_t \mid x_t), so you have to be able to write one down. It also stops the simulator at every observation, copies the state and restarts from it, so you have to be able to checkpoint the simulator. A compiled model you cannot open, someone else’s executable, or a reporting process nobody can put a density on: any of these rules the filter out and leaves ABC standing. Neither is true here, which is exactly why this is a good place to learn ABC and a poor argument for using it.

Three parameters are estimated, R0R_0, DinfD_\mathrm{inf} and ρ\rho, and the rest are fixed at the values the earlier sessions used. Every free parameter has to land inside the acceptance window at the same time, so the acceptance rate falls away sharply as the number of free parameters grows.

Approximate Bayesian computation

ABC: Making the distance explicit

A parametric likelihood settles three questions for you, quietly, as a consequence of the distribution you picked. ABC puts the same three in front of you and makes you answer them yourself:

  1. Summary statistics: which features of the data matter?
  2. Distance: how do we measure similarity?
  3. Threshold: how close is close enough?

That is the sense in which ABC makes the distance explicit. The choices were always there.

Here is a simple ABC rejection sampler from scratch:

"""
Simple ABC rejection sampler.
Samples from prior, simulates data, accepts if distance < threshold.
"""
function abc_rejection(prior_sampler, simulator, distance_fn, observed_data,
                      threshold, n_samples)
    samples = []
    n_attempts = 0
    max_attempts = n_samples * 1000  # Give up after many attempts

    while length(samples) < n_samples && n_attempts < max_attempts
        n_attempts += 1

        # Sample from prior
        θ = prior_sampler()

        # Simulate data
        simulated_data = simulator(θ)

        # Compute distance
        d = distance_fn(simulated_data, observed_data)

        # Accept if close enough
        if d < threshold
            push!(samples, θ)
        end
    end

    acceptance_rate = length(samples) / n_attempts
    println("Acceptance rate: $(round(acceptance_rate * 100, digits=2))%")
    println("Attempts needed: $n_attempts")

    ## The attempt count is returned as well as printed, so the comparison at the
    ## end of the session can put it beside the ABC-SMC simulation count
    return samples, n_attempts
end

NoteUnderstanding the distance functions

The three distance functions have different properties:

  • L1 (Manhattan): sum(|sim - obs|) - Sums absolute deviations. Robust to outliers because large errors contribute linearly. A mismatch of 20 cases counts twice as much as a mismatch of 10.

  • L2 (Euclidean): sqrt(sum((sim - obs)²)) - Root of squared deviations. The squared contribution of a mismatch of 20 is four times that of 10 (400 versus 100). If it is the only mismatch, the final Euclidean distance is twice as large because of the square root.

  • Weighted: sum(w × |sim - obs|) where w = 1/(obs + 1) - Weights inversely by observation size, so a mismatch of 5 when obs=2 is penalised more than when obs=50. This is an observation-scaled absolute error, useful when you care about relative fit; it is not a Poisson discrepancy.

When to use each:

  • L1: Good default. Robust to occasional large mismatches.
  • L2: When large deviations are particularly bad (e.g., outbreak peaks).
  • Weighted: When fit quality should be relative to the observed scale.

This is the same comparison as Poisson against negative binomial, which you met yesterday. A negative log-likelihood is a distance, and each observation model fixes how steeply that distance grows with one day’s discrepancy. Take an expected count of 5 and double a discrepancy from 10 cases to 20: L1 doubles, the squared error inside L2 quadruples, the Poisson negative log-likelihood multiplies by 3, and a negative binomial with dispersion 2 multiplies by 2.2. Poisson sits between the two distances, and the negative binomial lands close to L1. Near a good fit the Poisson term is about d2/2λd^2 / 2\lambda, which is the weighted distance above with squares in place of absolute values.

So choosing a distance and choosing an observation model are one decision, made twice: how steeply should a surprising observation count against you.

Run ABC with L1 distance:

WarningChoosing the threshold

ABC rejection sampling is sensitive to the threshold choice:

  • Too strict (e.g., 100): no acceptance was seen at this level in calibration runs, so it is likely to exhaust the attempt budget
  • Too loose (e.g., 1000): Fast, but approximate posterior is close to the prior
  • In between (e.g., 200-400): Runs quickly, but at the loose end of this band the posterior still carries a good deal of the prior

We start with a relaxed threshold (230) here. The run below accepts around 7% of what it proposes. By the guidance later in this session that is loose, and the posterior still holds a good deal of the prior. The exercise that follows asks you to tighten it.

If you get 0 samples: Increase the threshold (try 280, then 330). The sampler may be struggling to find parameter combinations that produce simulations close to the data. This can happen due to random variation - ABC is inherently stochastic.

TipExercise: Find a workable threshold

TipSolution

Tightening the threshold narrows the posterior but the acceptance rate collapses, so you wait much longer for the same number of samples: about 6% of prior draws are accepted at 230, roughly 1% at 190 and 0.2% at 165, so each step takes about five times as many simulations as the last. There is a practical floor as well. Over twenty thousand prior draws the closest any simulation came to these data was a distance of about 130, so acceptance below that was not observed and would be computationally inaccessible in this practical. This is empirical, not a hard mathematical bound: the count simulator can in principle produce a closer series. Some of the practical floor is the model and some of it is the noise: even at the particle MCMC parameters, two runs differ from the data by anywhere between 155 and 420.

Loosening it accepts almost everything, so the sampler is fast but the posterior drifts back towards the prior: you are no longer conditioning on the data very much.

There is no way to pick ϵ\epsilon from first principles. In practice you lower it until either the posterior stops changing or the acceptance rate becomes unaffordable, whichever comes first. This is exactly the weakness that ABC-SMC in the next section is designed to address, by walking the threshold down automatically.

A summary statistic in place of the series

distance_total throws away everything except the total number of cases, one number against fifty-nine. It is also on a different scale from distance_L1, so the two acceptance rates below can only be compared once you fix a threshold for each, and the thresholds here were picked to make them roughly comparable. The posteriors are what the comparison rests on.

TipWhat to look for

The acceptance rates are close, around 7% for L1 at 230 and around 7% for the total at 25, because the thresholds were chosen to make them so. The posteriors are not close.

R0R_0 centres near 4.7 on the total, against 5.6 on L1 and 6.4 from particle MCMC. The interesting part is where that difference does not show up. The 90% intervals are about equally wide, roughly 4.4 wide on the total and 4.3 on L1, so throwing away the timing has moved the posterior down instead of spreading it out. Both ABC intervals still cover the particle MCMC mean; the total’s sits lowest.

Many different epidemics produce 312 cases: a fast one that burns out, a slow one that grinds on, a small R0R_0 with a high reporting rate. The total cannot tell them apart, so it leaves R0R_0 and ρ\rho free to trade against each other, and the posterior settles lower down that trade than the full series allows.

Tightening from 25 to 12 halves the acceptance rate and moves the posterior almost not at all: the mean shifts by about 0.1 and the interval is unchanged. A tighter threshold on distance_L1 does pull the answer towards the particle MCMC one.

This is the difference between the two approximations ABC makes. The threshold is one, and more simulations get you out of it. The summary is the other, and you cannot: once the total is all you compare, no threshold recovers the timing information you discarded. A summary that is not sufficient puts a floor under the error, and ϵ→0\epsilon \to 0 does not lift it.

NoteABC-MCMC, and why this session does not use it

You have built Metropolis-Hastings twice in this course: once by hand in the MCMC session, and once with a particle filter supplying the likelihood in the particle MCMC session. ABC gives you a third version of the same loop. Propose a step, simulate once from the proposed parameters, and accept if that simulation lands within ε of the data. That is ABC-MCMC, introduced by Marjoram et al. (2003). The accept step is the Metropolis-Hastings one with the likelihood ratio deleted and the distance test put in its place; the prior ratio stays, and the priors here are not uniform, so nothing cancels.

"""
ABC-MCMC. Propose, test the prior ratio, then simulate once and accept if the
simulation lands within `threshold` of the data. Returns the chain and the
acceptance rate.
"""
function abc_mcmc(θ_start, simulator, distance_fn, observed_data, threshold,
                  n_iterations; proposal_sd = [0.4, 0.3, 0.05])
    chain = Vector{Vector{Float64}}(undef, n_iterations)
    θ = copy(θ_start)
    lp = log_prior(θ)
    n_accepted = 0

    for i in 1:n_iterations
        θ_proposed = θ .+ randn(length(θ)) .* proposal_sd
        lp_proposed = log_prior(θ_proposed)

        ## The prior ratio is checked first because it is free, and a proposal
        ## that fails it needs no simulation. The proposal is symmetric, so it
        ## contributes nothing to the ratio
        if isfinite(lp_proposed) && log(rand()) < lp_proposed - lp &&
           distance_fn(simulator(θ_proposed), observed_data) < threshold
            θ, lp = θ_proposed, lp_proposed
            n_accepted += 1
        end

        chain[i] = copy(θ) ## the state after the step, whether or not it moved
    end

    return chain, n_accepted / n_iterations
end

It stalls at a tight threshold, and the stochastic simulator is the reason. Run the model at one fixed parameter set and the L1 distance still moves from about 130 to about 420 between runs, because each run is a different epidemic. At a threshold near the bottom of that range a good parameter set fails the test most of the time and passes occasionally, so the chain accepts a step when it happens to draw a lucky epidemic and then cannot leave, because leaving requires another lucky epidemic from the proposed parameters. It is stuck on a realisation, and no proposal distribution addresses that, because the proposal is not what is being rejected. The exercise in Going further puts numbers on it.

ABC-SMC: Sequential Monte Carlo ABC

Both samplers so far run out of road well before the threshold is tight. Rejection sampling wastes almost everything it draws, because it searches from the prior every time and never learns where the good parameters were. ABC-MCMC does learn that, and seizes up as a result: at a tight threshold it accepts only lucky realisations and then cannot leave them. ABC-SMC (Sequential Monte Carlo ABC) gets round both by tightening the acceptance threshold across a sequence of generations, reusing the particles that survived the previous one.

The key idea, introduced by Toni et al. (2009), is:

  1. Start permissive: Begin with a loose threshold that accepts many samples
  2. Gradually tighten: Reduce the threshold across generations
  3. Reuse good samples: after the first generation, draw a parent from the survivors in proportion to its weight and perturb it, leaving the prior behind

The aim is to reach a threshold out of reach of rejection sampling, by refining particles that are already close. How much that saves depends entirely on the problem, the schedule and the kernel, so treat quoted speedup factors with suspicion until you have counted your own.

NoteImplementation: ABC-SMC

This is a simplified ABC-SMC for pedagogical purposes. It does compute the importance weights, which is what makes the sample valid, but production implementations (like ApproxBayes.jl or GpABC.jl) add adaptive thresholds and better perturbation kernels.

A perturbation landing outside the prior sends the loop back to its start, which draws a new parent as well as a new perturbation, so the proposal is the whole mixture restricted to the prior’s support. The constant that restriction introduces is the same for every particle, so it cancels when the weights are normalised, and the weights computed here are exact. Had the redraw kept the same parent and only re-perturbed, it would not cancel, and children of near-boundary particles would come out over-weighted.

Note on Threads.@threads: The code below uses Threads.@threads to parallelise the particle loop. The macro distributes iterations across available CPU threads, so each particle can be simulated concurrently. For this to have any effect, Julia must be started with multiple threads (e.g., julia -t auto). See the threading note in MCMC diagnostics for setup instructions. Without multiple threads, the loop runs sequentially (slower but still correct).

"Standard deviation of the perturbation kernel applied to a particle."
kernel_sd(θ) = 0.1 .* abs.(θ)

"Density of the perturbation kernel that moves `θ_from` to `θ_to`."
function kernel_pdf(θ_to, θ_from)
    sds = kernel_sd(θ_from)
    return prod(pdf(Normal(θ_from[d], sds[d]), θ_to[d]) for d in eachindex(θ_to))
end

"""
Simple ABC-SMC implementation.
Uses a sequence of decreasing thresholds, perturbing the particles that survived
the previous one. Returns the particles, their importance weights, the number of
simulations each generation cost, and the effective sample size of each
generation's weights.
"""
function abc_smc(prior_sampler, in_prior, simulator, distance_fn, observed_data,
                thresholds, n_particles; max_simulations_per_generation = 100_000)

    particles = Vector{Vector{Float64}}()
    weights = Float64[]
    sim_counts = Int[]
    ess_history = Float64[]

    for (t_idx, threshold) in enumerate(thresholds)
        println("\nGeneration $t_idx: threshold = $threshold")
        new_particles = Vector{Vector{Float64}}(undef, n_particles)
        simulations = Threads.Atomic{Int}(0)

        Threads.@threads for i in 1:n_particles
            while simulations[] < max_simulations_per_generation
                θ = if t_idx == 1
                    prior_sampler()
                else
                    # Draw a survivor in proportion to its weight, then perturb it
                    θ_old = particles[sample(1:length(particles), Weights(weights))]
                    θ_old .+ randn(length(θ_old)) .* kernel_sd(θ_old)
                end

                # A perturbation can leave the prior's support; redraw rather than
                # simulate, and do not count it as a simulation
                in_prior(θ) || continue

                Threads.atomic_add!(simulations, 1)
                if distance_fn(simulator(θ), observed_data) < threshold
                    new_particles[i] = θ
                    break
                end
            end
        end

        if !all(i -> isassigned(new_particles, i), 1:n_particles)
            error("gave up at threshold $threshold after $(simulations[]) " *
                  "simulations; loosen the schedule or raise the budget")
        end

        # Importance weights. A particle reached this generation through the
        # perturbation kernel rather than from the prior, and the weights undo
        # that: numerator is the prior density, denominator is how likely the
        # previous generation was to propose it. These priors are not uniform, so
        # the numerator has to be evaluated for each particle; with a uniform
        # prior it would be a constant that divided out. Skipping the weights
        # altogether leaves the sample biased towards wherever the kernel happens
        # to concentrate.
        new_weights = if t_idx == 1
            fill(1.0 / n_particles, n_particles)
        else
            w = [prior_pdf(new_particles[i]) /
                 sum(weights[j] * kernel_pdf(new_particles[i], particles[j])
                     for j in eachindex(particles))
                 for i in 1:n_particles]
            w ./ sum(w)
        end

        particles = collect(new_particles)
        weights = new_weights
        push!(sim_counts, simulations[])
        push!(ess_history, 1 / sum(abs2, weights))

        weighted_R_0 = sum(weights[i] * particles[i][1] for i in eachindex(particles))
        println("  Simulations: $(simulations[]),  weighted mean R_0: ",
                round(weighted_R_0, digits=2),
                ",  ESS: ", round(ess_history[end], digits=1), " of $n_particles")
    end

    return particles, weights, sim_counts, ess_history
end

ABC-SMC comes out ahead at this threshold, and further ahead on raw draws, where rejection sampling would need in the order of 100,000 simulations for 200 of them. The factor moves between runs, so take the ordering and the reason for it: ABC-SMC concentrates its effort where the data are without being told where that is, and that wins whenever prior acceptance at the threshold you want is small. At 230 it is not small, and rejection sampling is the better tool there.

The effective sample size printed for each generation measures a second problem. It starts at all 100 particles, which are drawn from the prior and weighted equally, and then drops. That is weight degeneracy, and it thins out the sample the final plots are drawn from:

Part of the apparent sharpness in those plots is duplication. Our sampler draws parents in proportion to weight, which spreads the next generation over the particles that hold it, but it never resets the weights when the effective sample size falls, and it never adapts the kernel width. Production implementations do both. Treat the final spread as indicative and do not report it as a posterior.

ImportantAssessing ABC posterior quality

Rejection ABC does not produce chains, so chain diagnostics like R-hat have nothing to work with. ABC-SMC produces weights, and the effective sample size of those weights tracks the same problem, as above. Beyond that, assess ABC posterior quality by:

  • Acceptance rate: Very low rates (< 0.1%) suggest the threshold is too strict or the model is a poor fit. Very high rates (> 10%) suggest the threshold is too loose and the posterior is close to the prior.
  • Visual comparison with likelihood-based posteriors: When a likelihood is available (as in this session), run both methods and compare. Large discrepancies suggest either the ABC threshold is too loose or the distance metric captures different features than the likelihood.
  • Threshold sensitivity: Run ABC with several thresholds. If the posterior changes substantially as you tighten the threshold, it has not yet converged, and you need a stricter threshold and more computation.
  • Coverage of prior: If the ABC posterior looks very similar to the prior, the threshold is too loose and the data are not informing the inference.
  • Replicate runs: Run ABC multiple times with different random seeds. If posteriors differ substantially between runs, you need more particles or a less strict threshold.

A posterior can be right about what the data determine and still look wrong parameter by parameter. Marginal histograms hide that, because they show each parameter with the others integrated away. Plot the pairs before concluding that two methods disagree.

Learning points

TipLearning points
  • ABC replaces the likelihood with an explicit distance, but choosing L1 over L2 over a weighted distance is the same kind of choice as picking Poisson over negative binomial
  • The acceptance threshold is the hard part: too tight and nothing is accepted, too loose and you are sampling the prior
  • ABC-SMC walks the threshold down in stages, concentrating effort where the data are without being told where that is, with weights that become uneven. It wins where prior acceptance at the threshold you want is small, and earns nothing at a loose threshold the prior already reaches
  • Comparing a summary instead of the whole series is the concession you cannot undo. A tighter threshold recovers what the tolerance gave up; nothing recovers what the summary discarded
  • The particle filter fits this model better than ABC does. ABC earns its place where the filter cannot run: no observation density to weight with, or a simulator you cannot stop and restart

Summary statistics for ABC

ABC often works better on carefully chosen summary statistics than on full time series. For epidemic data, useful summaries include:

  • Total cases: Sum of all observations
  • Peak timing: Day with maximum incidence
  • Peak height: Maximum daily incidence
  • Growth rate: Initial doubling time or exponential growth rate
  • Final size: Cumulative attack rate

Here is an example of how to define and use summary statistics for ABC:

"""Extract summary statistics from an epidemic time series."""
function epidemic_summaries(data)
    return [
        sum(data),                          # Total cases
        argmax(data),                       # Peak timing (day index)
        maximum(data),                      # Peak height
        sum(data[1:min(5, length(data))])   # Early cumulative cases (proxy for growth rate)
    ]
end

# Distance on summaries rather than full time series
function distance_summaries(sim, obs)
    s_sim = epidemic_summaries(sim)
    s_obs = epidemic_summaries(obs)
    # Normalise each summary by the observed value to make them comparable
    return sum(abs.(s_sim .- s_obs) ./ (abs.(s_obs) .+ 1.0))
end

Fewer, well-chosen summaries make ABC more robust to noise and model misspecification. Summaries that discard too much information produce wider posteriors. Which summaries to use is problem-specific, and finding out takes experimentation.

Try passing distance_summaries to abc_rejection in place of distance_L1 and compare the posteriors you get. The four summaries throw away the day-to-day shape of the curve, so expect them to widen. How much each parameter widens tells you how much of what identified it lived in the detail of the trajectory, beyond the peak, total and timing.

Robust distance metrics

For ABC with outliers or model misspecification, consider robust distances:

  • Median absolute deviation in place of mean squared error
  • Quantile-based distances that down-weight extreme values
  • Feature-based distances that focus on epidemiologically meaningful patterns

Try replacing distance_L1 in abc_rejection with a median-based version, distance_median(sim, obs) = median(abs.(sim .- obs)), and compare the posteriors. A robust distance stops a handful of large daily discrepancies dominating the fit, so how much the posterior moves tells you how much of it was being decided by a few days.
